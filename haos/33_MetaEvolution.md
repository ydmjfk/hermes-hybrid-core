## 🏛️ 風險分級元演進策略 (Risk-Based Meta-Evolution)

HAOS 確保演進機制本身隨系統規模自動適配，並對不同層級的變更實施嚴格風險分級：

```text
┌─────────────────────────────────────────────────────────────┐
│  Tier 1: 低風險修訂 (Skill 錯字、註解補充、Checklist 微調)    │
│  ↳ 跑分測試通過即可自動更新                                  │
├─────────────────────────────────────────────────────────────┤
│  Tier 2: 中風險修訂 (Workflow 狀態機、Planner Schema 調整)   │
│  ↳ 必須通過 A/B 沙盒測試與完整基準驗證                       │
├─────────────────────────────────────────────────────────────┤
│  Tier 3: 高風險/最高不變量 (00_Constitution, 核心權限矩陣)   │
│  ↳ 強制禁止自動修改，僅能導出提案供使用者人工審閱與 sudo 更新 │
└─────────────────────────────────────────────────────────────┘
```

---

## 🛡️ 元演進不變量
- 任何元演進操作不得破壞不可變核心（Immutable Core）。
- 每次演進必須在 [32_DecisionJournal.md](haos/32_DecisionJournal.md) 留下完整的 WHY 決策理由。
